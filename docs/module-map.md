# Module map

Update this file whenever a module is added, removed, or renamed.

## `upstream_agent/`

| Module | Purpose |
| --- | --- |
| `__init__.py` | Package root. Re-exports `__version__`. |
| `version.py` | Single-source `__version__` string. Read by `pyproject.toml` via `[tool.hatch.version]`. |
| `cli.py` | Typer CLI app. Exposes `init`, `status`, `check` (with `--camera` / `--api` / `--streaming`), and `run` subcommands plus a `--version` flag. Entry point is `upstream_agent.cli:app`. |
| `supervisor.py` | `RunResult` dataclass and `run_agent(cfg, state, *, client_factory=None, camera_factory=None, ffmpeg_factory=None, reporter_factory=None, ffmpeg_probe=None, save_progress=None, max_frames=None, max_attempts=None, backoff=None, ingest_timeout_s=15.0, ingest_poll_interval_s=0.5, camera_settle_s=1.5, camera_validation_window_s=5.0, camera_validation_frames=3, camera_read_retry_s=0.1, camera_release_settle_s=0.5, camera_unavailable_hint_after=3, on_event=None)`. Live streaming orchestrator powering `upstream run`. Outer recovery loop + private `_run_attempt` helper; the outer loop owns the camera + API client across attempts, each attempt owns its session / FFmpeg / heartbeat reporter and cleans them up in a `finally` (heartbeat → FFmpeg → session). End-to-end shutdown order is heartbeat → FFmpeg → session → camera → client. After FFmpeg starts the supervisor calls `_wait_for_remote_ingest`, which pumps frames into FFmpeg while polling `client.get_stream_session(session_id)` until the API reports `state="streaming"` — proof of *initial* MediaMTX ingest only; the event log is worded honestly and does not claim dashboard playback. `_reopen_camera_with_backoff` requires open + settle (`camera_settle_s`, 1.5 s) + windowed validation (`_validate_camera_reads` collects `camera_validation_frames` consecutive good reads inside `camera_validation_window_s`, retrying with `camera_read_retry_s` between reads); a `release_settle` (`camera_release_settle_s`) sits between close and the next open. After `camera_unavailable_hint_after` consecutive failed reopen cycles the helper emits a single `camera_unavailable_hint` event suggesting the operator restart the agent (macOS / Continuity Camera disconnect typically cannot recover in-process). The shared `BackoffPolicy` is never reset between reopen cycles. A try/finally inside the helper closes the camera even if `KeyboardInterrupt` raises from inside the validator. The outer loop classifies the per-attempt outcome via `_classify` (fatal / recoverable_stream / recoverable_camera), runs `_reopen_camera_with_backoff` on camera-side recovery, and sleeps via `BackoffPolicy` between stream-side attempts. The raw SRT URL lives in a single local variable inside `_run_attempt` and is dropped before attempt cleanup runs. Helpers `_register_if_needed` and `_start_session` propagate typed `ApiError` subclasses (no folding) so the classifier can branch correctly. `exit_reason` covers `completed`, `max_frames`, `keyboard_interrupt`, `ffmpeg_exited`, `fatal_heartbeat`. Hidden test knobs: `max_attempts` (default `None` = unbounded retry; `1` reproduces pre-M7 fail-fast), `backoff` (injected zero-delay policy for fast tests), and the ingest / camera timing kwargs (zero/tiny values keep recovery tests wall-clock-free). |
| `config.py` | YAML config loading (`load_config`), path resolution (`resolve_config_path`), and the default-config template writer (`write_default_config`). Pydantic v2 models for `api`, `camera`, `stream`, `logging`. |
| `state.py` | Local agent state: `State` model and `load_state` / `save_state`. Generates a stable `device_id` on first run. Handles corrupt state files by renaming to `.corrupt-<ts>`. |
| `logging_setup.py` | `setup_logging`, `TokenRedactionFilter`, and the pure `redact_token` helper. **Named `logging_setup` (not `logging`) to avoid shadowing the stdlib `logging` module.** |
| `errors.py` | Exception hierarchy: `UpstreamError` → `ConfigError`, `StateError`, `CameraError` (`CameraOpenError`, `CameraReadError`, `UnsupportedCameraSourceError`, `CameraDependencyMissingError`), `ApiError` (`ApiConnectionError`, `ApiAuthError` → `ApiTokenRevokedError`, `ApiTokenExpiredError`, `ApiValidationError`, `ApiRateLimitError`, `ApiServerError`, `ApiContractError`), `FfmpegError` (`FfmpegNotFoundError`, `FfmpegProbeError`, `FfmpegSrtUnsupportedError`, `FfmpegH264UnsupportedError`), `SrtUrlError`, `CommandBuildError`, `StreamingRuntimeError` (`FfmpegRuntimeError` → `FfmpegStartError`, `FfmpegWriteError`, `FfmpegExitError`). The CLI catches `UpstreamError` at the top level. |
| `sources/__init__.py` | Re-exports `VideoSource`, `WebcamSource`, `FrameInfo`. |
| `sources/base.py` | `VideoSource` ABC (`open`, `read_frame`, `close`, `is_open`, `info`, `last_error`) plus `FrameInfo` dataclass and concrete `__enter__`/`__exit__`. Today only `WebcamSource` implements it; the ABC stays in place so a future test-only file source can slot in without reshaping the runtime. |
| `sources/webcam.py` | `WebcamSource(VideoSource)` — wraps `cv2.VideoCapture`. Lazy `cv2` import via `_import_cv2()` so a missing OpenCV install becomes `CameraDependencyMissingError`. On macOS the capture is built with `cv2.CAP_AVFOUNDATION` explicitly when that constant is available, so the backend choice is deterministic; non-macOS platforms keep OpenCV's default selection. Writes width/height/fps before checking `isOpened()`; reports the effective values via `info`. `close()` is idempotent. |
| `diagnostics/__init__.py` | Documentation-only package marker for local diagnostic routines. |
| `diagnostics/camera.py` | `CameraCheckResult` dataclass and `run_camera_check(cfg)`. Never raises; the CLI translates the result to stdout / stderr / exit code. |
| `diagnostics/api.py` | `ApiCheckResult` dataclass and `run_api_check(cfg, state, *, client_factory=None, save_progress=None, capabilities=None)`. Walks the four-step API flow (register agent → register camera → start stream session → cleanup stop). Folds `ApiError` into the result; persists partial progress via the optional `save_progress` callback so a later step's failure does not lose earlier IDs. Defaults `capabilities` to a live FFmpeg probe (`{"ffmpeg": "<version>", "srt": <bool>}`) so the backend gets honest values. Exposes the private `_obtain_stream_approval` helper shared with the streaming orchestrator. The full SRT URL never appears on the result — only `srt_url_present: bool`. |
| `diagnostics/ffmpeg_check.py` | `FfmpegProbeResult` dataclass and `probe_ffmpeg(*, timeout_seconds=5.0, runner=None)`. Runs `ffmpeg -version` / `-protocols` / `-encoders` via a safe `subprocess.run` (no shell, captured stdout/stderr, timeouts, `FileNotFoundError`/`TimeoutExpired`/nonzero-exit handling). Detects SRT via a strict line-boundary regex (not `srtp`); picks an H264 encoder by priority (libx264 → h264_videotoolbox → h264_nvenc → h264_qsv → h264_amf). Never raises. The `runner` injection point lets tests stub subprocess. |
| `diagnostics/streaming.py` | `StreamingCheckResult` dataclass and `run_streaming_check(cfg, state, *, client_factory=None, save_progress=None, ffmpeg_probe=None)`. Eight-phase orchestrator: FFmpeg → SRT support → H264 encoder → API approval → SRT URL parse → command build → cleanup stop. Reuses `_obtain_stream_approval` from `diagnostics/api.py` so capabilities flow honestly through `register_agent`. The raw SRT URL stays in a local variable inside this function and is dropped before returning — only safe booleans and the approved config cross out. |
| `api/__init__.py` | Re-exports `UpstreamApiClient`, `ParsedError`, the path constants (including `HEARTBEAT_PATH` and `STREAM_SESSION_GET_PATH_TEMPLATE`), the token-code sentinels, and every schema (`Agent`, `Camera`, `Session`, `RequestedStreamConfig`, `ApprovedStreamConfig`, `Heartbeat`, `HeartbeatBatchRequest`, `HeartbeatBatchResponse`, `HeartbeatStatus`, plus request/response wrappers). |
| `api/client.py` | `UpstreamApiClient` — synchronous httpx wrapper. Public methods (`register_agent`, `register_camera`, `start_stream_session`, `stop_stream_session`, `get_stream_session`, `send_heartbeat`), one isolated `_build_auth_header` so swapping `Bearer` is one place, one `_request` (with optional `body` for GET-style calls and `params` for query strings) that handles JSON encode/decode and Pydantic-validated response parsing, and a status+code `_raise_for_status` that maps the confirmed error envelope (`error.code` / `error.message` / `error.request_id`) to typed `ApiError` subclasses. Endpoint path constants: `AGENT_REGISTER_PATH`, `CAMERA_REGISTER_PATH`, `STREAM_SESSION_START_PATH`, `STREAM_SESSION_STOP_PATH_TEMPLATE`, `STREAM_SESSION_GET_PATH_TEMPLATE`, `HEARTBEAT_PATH`. Token-code sentinels: `TOKEN_REVOKED_ERROR_CODE`, `TOKEN_EXPIRED_ERROR_CODE`. Never logs request or response bodies. |
| `api/schemas.py` | Pydantic v2 request/response models matching the confirmed contract. Request wrappers (`AgentRegisterRequest`, `CameraRegisterRequest`, `StreamSessionRequest`, `HeartbeatBatchRequest`) use `extra="forbid"`; response wrappers and nested objects (`Agent`, `Camera`, `Session`, `ApprovedStreamConfig`, `HeartbeatBatchResponse`) use `extra="ignore"`. `CameraRegisterResponse` has a pre-validator that accepts both wrapped (`{"camera": {...}}`) and flat camera bodies. Sensitive fields (`Session.srt_url`, `Session.streamid`, `StreamSessionResponse.session_token`) are accepted in the model but never exposed past the orchestrator. The `Heartbeat` model enforces the same bounds the server-side schema does (`fps` 0..1000, `bitrate_kbps` 0..200000, `width` 1..7680, `height` 1..4320, `codec` ≤32 chars, `last_error` ≤512 chars, `agent_version` ≤64 chars). |
| `runtime/__init__.py` | Re-exports `RuntimeStats`, `StatsSnapshot`, `BackoffPolicy`, and the four backoff defaults (`DEFAULT_INITIAL_DELAY_S`, `DEFAULT_MAX_DELAY_S`, `DEFAULT_MULTIPLIER`, `DEFAULT_JITTER_FACTOR`). |
| `runtime/stats.py` | `RuntimeStats` — thread-safe counters updated by the frame loop and read by the heartbeat thread. Internal `threading.Lock` guards `frames_written`, the 60-frame monotonic FPS window, `camera_connected`, `ffmpeg_running`, `last_frame_at`, and `last_error`. `record_frame(monotonic=None, wall_clock=None)` increments the counter and updates the window. `record_error(message)` stores the message (truncated to 512 chars). `snapshot()` returns a frozen `StatsSnapshot` dataclass with FPS computed as `(window-1)/(window[-1] - window[0])` once at least two frames have been recorded. Both `record_frame` arguments are injection points for deterministic tests. |
| `runtime/backoff.py` | `BackoffPolicy(*, initial=1.0, multiplier=2.0, max_delay=30.0, jitter_factor=0.2, rng=None)` — bounded exponential backoff with ±20 % multiplicative jitter. `next_delay()` returns the next delay and advances the internal geometric step (capped at `max_delay`); `reset()` returns to initial; `sleep(delay, shutdown)` builds on `threading.Event.wait` so a shutdown signal wakes the wait immediately rather than holding the agent through the full delay. The `rng` injection point lets tests assert progression deterministically. |
| `heartbeat/__init__.py` | Re-exports `HeartbeatReporter` and `DEFAULT_HEARTBEAT_INTERVAL_S`. |
| `heartbeat/reporter.py` | `HeartbeatReporter` — owns one daemon `threading.Thread` that POSTs a heartbeat every `interval_s` (default 5.0) seconds. Built with `client`, `agent_id`, `camera_id`, `session_id`, `agent_version`, `approved` (the `ApprovedStreamConfig`), and `stats`. Loop: snapshot stats → build `Heartbeat` → `client.send_heartbeat(...)` → sleep on `stop_event` for the interval. The wire `HeartbeatStatus` is `"streaming"` when `stats.snapshot().ffmpeg_running` is true and `"error"` otherwise — the reporter is **session-scoped** (torn down between recovery attempts) so the schema's `"reconnecting"` literal is not emitted in practice. Transient `ApiError` failures log a warning and continue; `ApiTokenRevokedError` / `ApiTokenExpiredError` / `ApiValidationError` set a stored fatal reason that the supervisor polls via `fatal_reason()`. `stop(timeout=2.0)` sets the stop event and joins; idempotent. The reporter never receives the SRT URL, streamid, or session token. |
| `encoder/__init__.py` | Re-exports `build_ffmpeg_command`, `redact_command`, and `FfmpegEncoderProcess`. |
| `encoder/command_builder.py` | `build_ffmpeg_command(*, width, height, fps, bitrate_kbps, codec, encoder, latency_mode, srt_url) -> list[str]` builds the argv FFmpeg runs in `upstream run`; raises `CommandBuildError` for non-H264 codecs or unknown encoders. Input shape is `-f rawvideo -pix_fmt bgr24 -s WxH -r FPS -i pipe:0` (OpenCV BGR frames piped to stdin). Output is H264/MPEG-TS over SRT. `redact_command(cmd, srt_url) -> list[str]` returns a fresh list with any element starting with `srt://` (or equal to the URL) replaced by `srt://<redacted>`; never mutates the input. |
| `encoder/ffmpeg.py` | `FfmpegEncoderProcess(command, redacted_command=None, *, popen_factory=None)`. Owns one `subprocess.Popen` running ffmpeg with `shell=False`, `stdin=PIPE`, `stdout=DEVNULL`, `stderr=PIPE`. Methods: `start()` (raises `FfmpegStartError` on `FileNotFoundError`/`OSError`; idempotent guard), `write_frame(bytes)` (raises `FfmpegWriteError` on `BrokenPipeError`/`OSError` — error messages scrub any `srt://` line out of FFmpeg's own stderr), `poll() -> int | None`, `stop(timeout_seconds=5.0)` (closes stdin, terminates, kills after timeout; never raises; idempotent). The `redacted_command` is the only argv shape exposed via `__repr__` and error strings. `popen_factory` injection point lets tests drive a fake `Popen` without launching any subprocess. |
| `transport/__init__.py` | Re-exports `ParsedSrtUrl` and `parse_srt_url`. |
| `transport/srt.py` | `parse_srt_url(url) -> ParsedSrtUrl`. Validates scheme (`srt`), host, and port; raises `SrtUrlError` otherwise. Returns only safe-to-display metadata (`has_host`, `has_port`, `port`, `has_streamid` as a bool, `mode`, `latency_ms`). The raw URL, hostname, and streamid are never stored on the dataclass — they stay in the caller's local scope. |

## Deferred submodules (added in later milestones)

These directories are intentionally **not present** yet. They will be
added in the milestone that needs them so their shape is informed by
real requirements, not premature placeholders. See
`architecture.md` "Honest gaps and planned work (M8 candidates)" for
the up-to-date motivation and target shape of each.

| Path | Milestone | Purpose |
| --- | --- | --- |
| `buffer/frame_buffer.py` | M8 candidate | Bounded ring buffer between source and encoder. Consumes `StreamConfig.buffer_ms` (already in the schema). |
| `api/config_fetch.py` | M8+ | Additional HTTP call (get-config) for dashboard-driven config rotation. |
| `diagnostics/network.py` | M8+ | Additional `upstream check --…` probes for API and streaming-server reachability. |

**Explicitly out of scope:** non-webcam input sources (RTSP, IP
camera). The agent is webcam-only by design; SRT remains the only
egress protocol. Adding alternate source types is not on the
roadmap.

## `examples/`

| File | Purpose |
| --- | --- |
| `webcam.yaml` | Ready-to-copy config for a local USB or built-in camera. The only example template. |
